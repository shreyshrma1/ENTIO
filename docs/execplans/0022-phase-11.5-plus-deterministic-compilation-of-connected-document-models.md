# ExecPlan: Phase 11.5+ Deterministic Compilation Of Connected Document Models

## Status

Implemented and verified on 2026-07-30.

This is the most recent Phase 11.5+ planning document and is authoritative for
delivery order, affected files, implementation slices, verification commands,
and stop conditions.

## Goal

Replace model-generated low-level Entio operations at the end of document
analysis with:

```text
verified connected document model
→ model-produced semantic plan
→ Kotlin completeness check
→ deterministic Kotlin compilation
→ existing semantic previews
→ grouped human review
→ existing private-draft and proposal workflow
```

The model decides intended meaning. Kotlin decides whether that meaning is
supported and, when it is, produces exact typed edits. No component in this
phase approves, applies, or writes ontology content automatically.

## Current State

- `DocumentAnalysisPipelineContracts.kt` defines discoveries, connected-model
  items, critic findings, temporary references, low-level plan operations,
  coverage dispositions, final recommendations, and current limits.
- The current final provider schema produces `DocumentFinalPlan` operations,
  including `DocumentPlanOperationKind`, operands, order, dependencies, and
  expanded edit counts.
- `OpenAiDocumentAnalysisClient` prompts for and parses those low-level
  operations.
- `DocumentChangeSetPlanVerifier` checks model-planned operation shapes,
  temporary references, kinds, sources, collisions, dependencies, and bounds.
- `DocumentRecommendationDraftTranslator` translates verified operations into
  existing typed edits.
- `DocumentAnalysisService` and `DocumentIngestionOrchestrator` own bounded
  stage execution and deterministic verification.
- `DocumentReviewWorkspace` and the React document-ingestion workspace show
  grouped recommendations and hand accepted typed changes to the existing
  proposal workflow.
- The existing two-PDF benchmark manifest is
  `web-server/src/test/resources/document-ingestion/phase-11.5-two-pdf-expectations.json`.
- Existing limits are 20 expanded edits per recommendation, 100 expanded edits
  per task, and 100 recommendations per task.

## Target State

- A provider-neutral semantic-plan contract replaces low-level model-planned
  operations.
- The provider returns semantic items, semantic groupings, rationale, evidence,
  proposed outcome, critic dispositions, and three model-owned confidence
  dimensions.
- A Kotlin pattern registry defines only mappings supported by existing typed
  ontology and SHACL operations.
- A Kotlin compiler resolves exact existing entities, creates temporary
  references and final IRIs, orders dependencies, expands patterns, enforces
  limits, and translates through existing typed edit services.
- A deterministic completeness gate gives every important discovery exactly one
  valid disposition.
- Semantic coverage and compilation success are calculated independently.
- Compilation confidence is Kotlin-owned and overall confidence uses the
  weakest applicable dimension.
- Unsupported complex rules remain review-only.
- The browser shows the semantic intent and exact compiled result without
  becoming a semantic editor or policy engine.
- The existing private-draft, proposal, approval, apply, reload, rollback, and
  applied-provenance paths remain the only write workflow.

## Important Discovery

A verified discovery is important when its category is:

- concept;
- relationship;
- requirement;
- control;
- conditional business rule;
- business fact;
- definition;
- non-illustrative individual.

Administrative metadata and purely illustrative examples are excluded from the
semantic-coverage denominator, but they still require an explicit recorded
disposition. A discovery must not be excluded merely because it is difficult to
model or compile.

## Review-Only Retention

A review-only finding is retained durably when either:

- it is linked to an applied executable or mixed recommendation; or
- the reviewer explicitly chooses **Retain as documented rule**.

A retained review-only finding remains non-executable, is not written into the
ontology, and is available to later document-ingestion comparisons. Rejected
and unretained review-only findings remain temporary.

## Controlled Provider Benchmark

The controlled ten-run provider benchmark is required before Phase 11.5+ can be
declared complete.

If verified provider credentials are unavailable, implementation and offline
verification may continue, but phase completion is blocked. Any waiver requires
explicit approval and must be recorded in the phase completion decision; no
waiver is implied by this ExecPlan.

## Dependency Order

```text
Slice 0 contract audit
→ Slice 1 neutral semantic contracts
→ Slice 2 completeness and metrics
→ Slice 3 pattern registry and compiler
→ Slice 4 references, ordering, limits, and translation
→ Slice 5 provider boundary and orchestration
→ Slice 6 grouped review and provenance
→ Slice 7 permanent benchmark and full regression
→ Slice 8 documentation and completion
```

Slices may be split into smaller commits, but later slices must not bypass the
listed dependencies.

  metrics, and confidence.
- Compiler pattern mappings, unsupported fallback, stable IDs and IRIs,
  dependency ordering, duplicate prevention, counts, splits, and blockers.
- Completeness and critic ledgers.

### Integration Tests

- Strict provider response to verified semantic plan.
- Semantic plan through completeness, compilation, previews, review, typed

  approval, apply, reload, and rollback.

## Rollback Notes

- Keep each slice in a focused commit so contracts, compiler behavior,
  orchestration, UI, and documentation can be reverted independently.
- Until Slice 5 is complete, the old runtime path may remain available only as
  a development migration aid.
- After activation, new tasks must not silently fall back to the old low-level
  planner. Rollback means reverting the Phase 11.5+ release as a whole, not
  mixing contracts within one task.
- Existing applied ontology changes and applied document provenance must remain
  readable. Do not delete or rewrite them during rollback.
- Temporary semantic plans and incomplete tasks may be cleared through existing
  cancellation, deletion, and restart cleanup.
- No database or ontology-source migration is expected.

## Risks And Assumptions

- The current typed edit surface may support fewer SHACL patterns than the scope
  examples suggest. Slice 0 must pin the exact safe subset; unsupported meaning
  stays review-only.
- Semantic plans can still vary because they are model-produced. The compiler
  removes formatting variation but cannot guarantee correct modeling judgment.
- A strict semantic schema may increase provider correction rates. Existing
  bounds remain authoritative.
- Deterministic splitting is safe only for independently coherent dependency
  closures. Some large groups will remain blocked.
- Adding `MatchedExisting` and `Blocked` coverage outcomes may require a
  versioned web DTO. It must not require new persistence.
- Compilation confidence is meaningful only for executable items and must be
  explicitly absent for review-only groups.
- Real-provider cost fields may not always be available. Token usage and
  duration are acceptable comparison data when cost is unavailable.
- The two existing PDFs and their expectation manifest remain available and
  legally appropriate as permanent fixtures.
- Verified provider credentials are required for the controlled benchmark
  before completion unless the user explicitly approves a recorded waiver.

## Definition Of Done

Phase 11.5+ is done only when:

- the final model contract contains semantic meaning and no low-level Entio
  operations or final IRIs;
- all approved semantic patterns compile deterministically through existing
  typed edits;
- completeness, reference, kind, source, duplicate, collision, freshness,
  dependency, count, split, and preview checks pass;
- unsupported complex rules remain review-only;
- semantic coverage and compilation success are separately visible;
- compilation and overall confidence follow the specified rules;
- grouped review remains understandable and server-authoritative;
- mixed applied provenance retains related review-only meaning;
- pure review-only findings are retained durably only after the reviewer chooses
  `Retain as documented rule`;
- the existing human approval, proposal, apply, reload, and rollback path is
  unchanged;
- the offline suite and controlled ten-run benchmark meet every acceptance
  target, or an explicit benchmark waiver is approved and recorded;
- all full verification commands pass;
- documentation reflects verified behavior and the phase summary is complete.

## Boundary Check

- **Fits the requested phase:** yes. The user explicitly requested planning for
  Phase 11.5+, and the work changes only the final document-analysis boundary.
- **Avoids current non-goals:** yes. It adds no automatic apply, raw RDF,
  unrestricted agent, persistence layer, CLI surface, or VS Code surface.
- **Avoids speculative infrastructure:** yes. Existing modules, provider
  orchestration, typed edits, proposal services, and provenance are reused.
- **Preserves module ownership:** yes. Core owns neutral records, the semantic
  engine owns deterministic compilation, Ktor owns orchestration and
  authorization, and React owns presentation.
- **Uses existing semantic-web tooling:** yes. The compiler targets current
  typed ontology and SHACL services and does not implement RDF, OWL, or SHACL
  standards itself.
